# [`LeetCode` 126. 单词接龙 II](https://leetcode.cn/problems/word-ladder-ii/description/)

## 一、题目核心

给定 `beginWord`、`endWord` 和 `wordList`，每次只能改变一个字符，要求返回从起点到终点的**所有最短转换序列**。

本题有两个目标：

1. 找到最短转换距离。
2. 找出所有达到这个最短距离的路径。

因此，不能只用普通 BFS 找到终点就结束，也不能只记录每个单词的一个前驱。

## 二、整体思路：BFS + 反向图 + DFS

### 1. 建立模式表，快速寻找相邻单词

两个单词只差一个字符，就可以互相转换。

例如：

* `hot` → `*ot`、`h*t`、`ho*`
* `dot` → `*ot`、`d*t`、`do*`

使用模式作为键，将对应单词存入哈希表：

```cpp
unordered_map<string, vector<string>> mp;

for (const string& word : wordList) {
    for (int i = 0; i < word.size(); ++i) {
        string pattern = word;
        pattern[i] = '*';
        mp[pattern].push_back(word);
    }
}
```

查询单词 `hot` 的邻居时，只需要枚举它的所有模式，再查找对应列表。

注意：`*` 是占位符，表示该位置不同，其余字符相同。

### 2. BFS 求最短距离，同时建立反向图

定义：

```cpp
dist[word] = beginWord 到 word 的最短距离
```

起点初始化：

```cpp
dist[beginWord] = 0;
```

反向图的定义：

```cpp
graph[v] = 所有能够一步到达 v 的单词
```

例如，若 `hot` 可以转换为 `dot`，则记录：

```cpp
graph["dot"].push_back("hot");
```

为什么建立反向图？

因为最后从 `endWord` 开始 DFS，就能沿着前驱一步步回到 `beginWord`，还原完整路径。

### 3. BFS 的关键：区分第一次到达和同距离到达

对于当前单词 `u` 和邻居 `v`：

```cpp
if (!dist.count(v)) {
    dist[v] = dist[u] + 1;
    q.push(v);
    graph[v].push_back(u);
}
else if (dist[v] == dist[u] + 1) {
    graph[v].push_back(u);
}
```

两种情况：

* **第一次到达 `v`**：记录距离、入队、记录前驱。
* **再次通过同样短的路径到达 `v`**：只记录新的前驱，不必重复入队。

不能简单地在第一次访问后就丢弃所有后续路径，否则可能漏掉答案。

也不能不加判断地把所有邻居入队，否则会反复访问、重复建边，甚至因循环转换而无法结束。

### 4. DFS 还原所有最短路径

因为 `graph` 保存的是反向边，所以从 `endWord` 开始递归。

```cpp
path.push_back(cur);

if (cur == beginWord) {
    // 找到一条完整路径
} else {
    for (const string& pre : graph[cur]) {
        dfs(pre);
    }
}

path.pop_back();
```

此时 `path` 的顺序是从终点到起点。找到完整路径后，将它反转，再加入答案。

**注意：** `path` 是 `vector<string>`，不能使用 `ret + e` 拼接。应使用 `push_back()` 和 `pop_back()` 进行回溯。

## 三、最容易出错的地方

1. **只记录一个前驱**：会漏掉其他最短路径。
2. **不记录距离**：无法判断某条边是否属于最短路径。
3. **每次遇到邻居都入队**：产生大量重复访问。
4. **忽略单词自身**：模式表中可能查到当前单词，需要跳过 `v == u`。
5. **没有判断终点是否存在**：若 `endWord` 不在 `wordList` 中，直接返回空数组。
6. **DFS 路径拼接错误**：字符串不能直接加到 `vector<string>` 上。
7. **反向图与路径顺序混淆**：反向图从终点 DFS，最终路径需要反转。

## 四、做题时的思考顺序

1. 单词之间如何判断是否相邻？能否用模式表加速？
2. 只求最短距离，用什么算法？—— BFS。
3. 为什么不能只保存一个前驱？—— 题目要求所有最短路径。
4. 如何判断一个前驱是否属于最短路径？—— `dist[pre] + 1 == dist[cur]`。
5. 如何枚举所有答案？—— 反向图 DFS + 回溯。
6. 如何避免重复入队和循环？—— 通过距离表控制 BFS。

## 五、复杂度

设单词长度为 `L`，单词数量为 `N`。

* 建立模式表：约 `O(NL²)`，因为生成和复制长度为 `L` 的字符串需要时间。
* BFS：取决于模式表中邻居列表的总扫描次数，以及字符串操作开销。
* DFS：与所有最短路径的总输出规模有关；最短路径数量可能呈指数增长。

因此，本题的主要难点不仅是找到最短距离，更是**完整保留所有最短路径的前驱关系**。
