c++左闭右开，注意区间
unique返回最后一个的下一个指针
🚨 误区一：离散化的“半残”空间与边界这是 90% 的初学者在第一次写离散化时都会流血的地方，
主要集中在三个微小的边界偏差：只存一半变量： 题目给了 n 个条件，每个条件有 x 和 y 两个变量。
最终不同的变量数其实是 2n 个。数组如果没有开到 2n，或者像最开始那样只循环了 n 次去处理排序，
后半截数据就成了乱码。无视 C++ 的“左闭右开”原则： sort 和 unique 接受的区间是 [first, last)
不包含 last。如果你的数据存到了 a[2*n]，一定要写成 sort(a + 1, a + 2 * n + 1)，少加这个 1，
最后一个元素永远排不上。算错去重后的总个数： unique 返回的是去重后尾部的指针。要得到实际的元素个数，
必须减去你真正的起始地址。如果数据从 a[1] 开始存放，必须是 unique(...) - (a + 1)，写成 - a 会导致多出一个未知的虚假元素。


🚨 误区二：并查集初始化的“刻舟求剑”用原题的 n 去初始化 fa 数组： 
很多同学肌肉记忆般地在输入 n 后立刻写下 for(i=1; i<=n; i++) fa[i]=i;。
致命后果： 离散化后，你的变量 ID 最大可以达到 2n。如果你只初始化到 n，
当查询一个离散化映射值为 n+1 的节点时，它的父节点是默认的 0。这会让 find 函数顺着 0 一直往下找，
导致并查集逻辑直接雪崩。铁律： fa 数组的初始化必须放在离散化彻底完成之后，并且要循环到去重后的总个数 end。


🚨 误区三：被题目输入顺序牵着鼻子走边读边做： 题目按什么顺序给条件，
代码就按什么顺序 unin（合并）和 issame（查询）。逻辑漏洞： 在这道题中，
相等具有传递性（1=2, 2=3 推导出 1=3），而不等没有。如果先处理了 1≠3，
再去合并 1=2 和 2=3，就会因为错过全局视野而导致误判。铁律： 涉及到矛盾判定的题，
必须对操作进行优先级排序。永远是先处理“建设性”操作（如相等的合并），再去处理“核查性”操作（如不等式的冲突检验）。



🚨 误区四：迷信高级 STL 导致性能翻车滥用 map / unordered_map 充当离散化映射： 
虽然写着爽，但 std::map 的红黑树常数极大，在 1e6 级别的数据量下极易 TLE（超时）；
而 std::unordered_map 虽然理论复杂度是 O(1)，但在遇到特定的竞赛造数据手法时，
极易发生哈希碰撞，直接退化成 $O(N)$。正解： 排序数组 + std::lower_bound 才是离散化映射的最终归宿。
二分查找不仅常数极小，而且不需要额外开辟复杂的节点空间，是算法竞赛中的性能天花板。
