# 并查集 & 离散化 避坑指南

---

## 🚨 误区一：离散化的"半残"空间与边界

90% 的初学者在第一次写离散化时都会流血，集中在三个微小边界：

### 1. 只存一半变量
题目给了 $n$ 个条件，每个条件有 $x$ 和 $y$ 两个变量。最终不同的变量数其实是 $2n$ 个。数组没开到 $2n$，后半截数据就成了乱码。

### 2. 无视 C++ 的"左闭右开"原则
`sort` 和 `unique` 接受的区间是 `[first, last)`，不包含 `last`。数据存到 `a[2*n]`，必须写成：

```cpp
sort(a + 1, a + 2 * n + 1);  // 少 +1，最后一个元素永远排不上
```

### 3. 算错去重后的总个数
`unique` 返回的是去重后尾部的指针。得到实际元素个数，必须减去起始地址：

```cpp
int end = unique(a + 1, a + 2 * n + 1) - (a + 1);  // 数据从 a[1] 开始存放
// 写成 -a 会多出一个虚假元素
```

## 🚨 误区二：并查集初始化的"刻舟求剑"

### 典型错误
肌肉记忆在输入 $n$ 后立刻 `for(i=1;i<=n;i++) fa[i]=i;`

### 致命后果
离散化后变量 ID 最大可达 $2n$。若只初始化到 $n$，当查询映射值为 $n+1$ 的节点时，父节点为默认的 $0$，`find` 函数顺着 $0$ 找，并查集逻辑直接雪崩。

### 铁律
`fa` 数组的初始化必须放在**离散化彻底完成后**，循环到去重后的总个数 `end`：

```cpp
for (int i = 1; i <= end; i++) fa[i] = i;
```

## 🚨 误区三：被题目输入顺序牵着鼻子走

### 边读边做的陷阱
题目按什么顺序给条件，代码就按什么顺序 `unite` / `check`。

### 逻辑漏洞
相等有传递性（$1=2,\ 2=3 \Rightarrow 1=3$），不等没有。先处理 $1 \ne 3$，再合并 $1=2$ 和 $2=3$，会因缺少全局视野而误判。

### 铁律
涉及矛盾判定的题，必须对操作进行**优先级排序**：
1. **先**处理"建设性"操作（相等 → 合并）
2. **再**处理"核查性"操作（不等 → 冲突检验）

## 🚨 误区四：迷信高级 STL 导致性能翻车

| 做法 | 问题 |
|------|------|
| `std::map` 做离散化映射 | 红黑树常数极大，$10^6$ 级别极易 TLE |
| `std::unordered_map` 做映射 | 竞赛造数据手法下哈希碰撞退化成 $O(N)$ |

### 正解
```cpp
// 排序数组 + lower_bound 才是离散化的最终归宿
sort(a + 1, a + 1 + total);
int end = unique(a + 1, a + 1 + total) - (a + 1);
int id = lower_bound(a + 1, a + 1 + end, x) - a;  // 常数极小，不需额外空间
```

## 并查集进阶专题

| 专题 | 要点 | 例题 |
|------|------|------|
| **扩展域并查集** | 维护多个域（如同类/天敌），理清关系切勿漏掉 | P2024 食物链 |
| **带权并查集** | `find` 时维护到根的距离/权值，`unite` 时更新关系 | P1196 银河英雄传说 |

### 带权并查集核心框架
```cpp
int fa[N], d[N];  // d[x]: x 到 fa[x] 的权值

int find(int x) {
    if (fa[x] == x) return x;
    int root = find(fa[x]);
    d[x] += d[fa[x]];   // 路径压缩时累加权值
    return fa[x] = root;
}

void unite(int a, int b, int w) {  // w: a 和 b 的关系权值
    int ra = find(a), rb = find(b);
    if (ra != rb) {
        fa[ra] = rb;
        d[ra] = d[b] - d[a] + w;   // 向量运算
    }
}
```
