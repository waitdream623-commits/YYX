# ACM 形式比赛实战技巧

> 适用：ICPC 赛制（实时评测、罚时、封榜）及类似 OI 赛制

---

## 一、赛前准备（比赛前一天）

### 1.1 环境检查清单
- [ ] 确认 IDE/编辑器配置正常（代码补全、编译快捷键）
- [ ] 准备一份精简的纸质/电子模板：
  - 快读快写（`read()/print()`）
  - 常用算法模板（二分、前缀和、并查集、线段树、最短路、KMP 等）
  - 常用常数（`INF=0x3f3f3f3f`、`MOD=1e9+7`）
- [ ] 确认编译器版本和命令（`-std=c++17` 或 `-std=c++20`）
- [ ] 准备好对拍脚本（暴力 vs 正解）
- [ ] 调试宏准备好（`#define debug(x) cerr << #x << " = " << x << endl`）

### 1.2 身体准备
- 赛前一晚睡够 7 小时，不要通宵"抱佛脚"
- 比赛前吃点东西但不要吃撑（血糖波动影响注意力）
- 准备水和零食（巧克力/坚果，低 GI 食物）

## 二、开赛策略（前 30 分钟）

### 2.1 读题顺序
```
不要从 A 开始死磕！
1. 快速扫完所有题目（5-10 分钟）
2. 每道题标注：
   - 「签到」：一眼会 → 马上写
   - 「可做」：有思路但需要推敲 → 排优先级
   - 「困难」：没思路 → 先放着
   - 「不可做」：完全不会 → 放弃
```

### 2.2 优先级排序
| 优先级 | 题目特征 |
|--------|----------|
| 🥇 最高 | 签到题，5 分钟内可 AC |
| 🥈 高 | 通过人数多 + 你有思路 |
| 🥉 中 | 通过人数中等 + 你觉得能做 |
| 💤 低 | 通过人数极少 / 你没思路 |

**铁律：先做通过人数多的题，而不是你觉得会做的题。** 通过人数 = 难度投票。

### 2.3 签到题注意事项
- 签到题 WA 了 **立刻停手**，重新读题——大概率是读错题了
- 不要因为简单就省略必要的检查（n=1、负号、输出格式）
- ICPC 赛制下，签到题 WA 一次，罚时 20 分钟——相当于一道中等题白做

## 三、编码阶段技巧

### 3.1 写代码前（1-3 分钟思考）
```
✅ 在纸上/脑子里跑一遍样例
✅ 想清楚边界：n=0? n=1? 负数? 重复元素? 空输入?
✅ 确认数据类型：是否需要 long long? 是否需要 __int128?
✅ 估计复杂度：最坏情况跑得过吗？
```

### 3.2 编码习惯
```cpp
// 1. 多测清空，养成肌肉记忆
int T; cin >> T;
while (T--) {
    // 所有全局数组/变量在这里清零
    memset(arr, 0, sizeof arr);
    // ...
}

// 2. 变量命名有意义（比赛不是写工程，但也不要全用 a,b,c,x,y）
int maxVal, minIdx, leftPtr;  // 好
int a, b, c, x, y, z;         // 差（半小时后你自己都看不懂）

// 3. 提前写好调试开关
#ifdef DEBUG
#define dbg(x) cerr << #x << " = " << x << endl
#else
#define dbg(x)
#endif
```

### 3.3 常见 bug 自检清单（提交前必看）
- [ ] `int` 会不会溢出？ → 换 `long long`
- [ ] 数组开够了吗？ → `const int N = xxx + 10`
- [ ] 多测清空了吗？ → 全局变量、队列、栈、vector
- [ ] 模运算做了吗？ → `(a + b) % MOD`
- [ ] 输出格式：空格？换行？末尾空格？Yes/YES？
- [ ] 0-indexed vs 1-indexed 搞混了没？

## 四、调试技巧

### 4.1 分层调试
```
WA 了不要乱改代码，按顺序排查：

1. 读题：再看一遍题目，确认没有漏条件
2. 极端数据：手工构造 n=1、n=最大、全相等、单调增/减
3. 打印中间变量：关键位置的数组值、循环次数
4. 对拍：写暴力程序，随机小数据对比
5. 特殊边界：0、负数、INT_MAX、MOD
```

### 4.2 快速对拍模板
```cpp
// 假设 solve() 是你的正解，bf() 是暴力
// 用命令行重定向或手动循环
while (true) {
    int n = rand() % 10 + 1;
    // 生成随机数据...
    int ans1 = solve();
    int ans2 = bf();
    if (ans1 != ans2) {
        cout << "WA! " << ans1 << " " << ans2 << endl;
        break;
    }
    cout << "OK" << endl;
}
```

### 4.3 卡住时该做什么
```
⏱ 一道题超过 30 分钟没进展 → 立即切换

原因：
- 继续死磕的边际收益极低
- 先去拿其他题的分数
- 换题后潜意识还在后台处理，回来时可能有新思路

不要有"我都做了这么久不能放弃"的沉没成本谬误
```

## 五、时间管理

### 5.1 理想时间分配（5 小时，ICPC）
| 时间段 | 任务 |
|--------|------|
| 0~30min | 读完所有题，AC 签到题 |
| 30min~2h | 主攻高优先级题，争取 3~4 题 |
| 2h~4h | 攻坚中等题，保证 5~6 题 |
| 4h~5h | 封榜后冲刺，挑最有把握的做 |

### 5.2 最后 1 小时策略
```
- 不要再开没见过的新题（除非一眼会）
- 优先修复已有代码的 bug（已经投入时间，修复成本低）
- 如果有多道题都 WA，选 WA 次数最少的那道先修
- 最后 15 分钟不要改代码了，检查已 AC 的题目有没有多交的
```

## 六、ICPC 赛制特有技巧

### 6.1 罚时规则
- 每道题的罚时 = 从比赛开始到 AC 的分钟数 + WA 次数 × 20
- 没 AC 的题不计罚时
- **所以：不确定的代码先不要交！** 宁可花 5 分钟多测几组，也不冒罚时的风险

### 6.2 封榜策略
- 最后一小时榜单冻结
- 封榜前：根据已有排名决定策略（保牌 vs 冲击更高奖）
- 封榜后：就当没榜单了，专注做题，不要猜自己在什么位置

### 6.3 气球效应
- 每 AC 一道题会得到一个气球
- 可以通过观察其他队的气球颜色判断他们过了哪些题
- 如果你还没有某个颜色的气球，那题可能值得看看

## 七、心理调节

### 7.1 卡题时
- 深呼吸 30 秒，去趟厕所，洗把脸
- 告诉自己：不是你一个人卡，大家都卡
- 回来后**重读题目**而非重读代码——很多时候是题意理解错了

### 7.2 WA 多次时
- 停止提交至少 15 分钟
- 把代码打印出来（或放大字号），一行一行看
- 找人帮你 code review（如果是团队赛）
- 完全重写有时候比修 bug 更快

### 7.3 排名焦虑
- 前 1 小时排名没有参考价值（强队还在读题，弱队签到题 AC 完就没了）
- 不要频繁刷新排行榜，每半小时看一眼就够了
- 专注于自己能控制的：下一道题的 AC

---

## 八、赛后复盘（比你想象的重要）

### 8.1 必做
- 当天补掉赛中没有 AC 的题（趁记忆还在）
- 记录每道题的卡点：是读题？是算法？是实现？是调试？
- 如果是算法不会 → 补专题
- 如果是实现 bug → 下次写代码时重点检查

### 8.2 错因追踪
你已经在 `note.md` 里有很好的错因体系了，比赛后对照填：
- `边界` → 赛前把 n=0/1/负数的检查写进代码模板
- `类型` → 养成 `#define int long long` 或勤用 `1LL*` 的习惯
- `初始化` → 多测清空模板标准化
- `读题` → 以后读题时强制自己复述一遍题意

## 九、速查：按题号快速决策

| 题目表现 | 策略 |
|----------|------|
| AC 人数 50%+ | 必须做出来 |
| AC 人数 20~50% | 你有思路就做 |
| AC 人数 5~20% | 评估是否在你擅长领域 |
| AC 人数 <5% | 除非你很确定，否则先放 |
| 你 WA 了 3 次 | 停手，15 分钟后再看 |
| 你 WA 了 5 次 | 考虑换人重写（团队）/完全重写（个人） |
| 一题卡 40 分钟 | 换题 |
| 比赛剩 30 分钟 | 不再开新题，只修已有 bug |

---

> **最重要的技巧：享受比赛。** 你大一就有这么好的底子，ACM 是你成长的加速器，不是你的全部定义。每一场比赛，不管成绩如何，你都在变强。
