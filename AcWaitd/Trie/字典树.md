# 字典树 Trie

## 解决问题

- **普通字典树**：一堆字符串的**前缀**问题 —— 插入、查是否存在、查"有多少串以 s 为前缀"、按字典序枚举。
- **01-Trie**：把整数**按二进制位当字符**，解决"异或意义下最优"的问题 —— 最大异或对、异或第 k 大、区间最大异或和。
- 共同点：**共享公共前缀**，用空间换时间。核心操作复杂度只跟"串长 / 位数"有关，跟"有多少个串"无关。

## 两种形态

| 形态 | 一条边代表 | 字符集 K | 典型问题 |
| --- | --- | --- | --- |
| 普通字典树 | 一个字符 | 小写 26 / 大小写+数字 62 | 前缀计数、模式串存在性 |
| 01-Trie | 一个二进制位 | 2 | 最大异或对、异或第 k 大、区间异或 |

## 普通字典树（62 叉版）

~~~ cpp
const int N = 3e6 + 10;          // ⚠️ 内存重灾区，见下面「内存」一节
int tree[N][62], p[N], e[N];     // 62 = 小写 26 + 大写 26 + 数字 10
int idx;                         // 已分配的节点编号，根固定为 0

int get_num(char c)              // 字符 → 边编号
{
    if (c >= 'a' && c <= 'z') return c - 'a';
    if (c >= 'A' && c <= 'Z') return c - 'A' + 26;
    return c - '0' + 52;
}

void insert(string &s)
{
    int cur = 0;                 // 从根开始
    p[cur]++;
    for (char c : s)
    {
        int path = get_num(c);
        if (tree[cur][path] == 0) // 0 = 这条边还不存在
            tree[cur][path] = ++idx;   // 开新节点
        cur = tree[cur][path];
        p[cur]++;                // 经过该节点的串数 +1
    }
    e[cur]++;                    // 在该节点结束的串数 +1
}

int query_prefix(string &s)      // 有多少串以 s 为前缀
{
    int cur = 0;
    for (char c : s)
    {
        int path = get_num(c);
        if (tree[cur][path] == 0) return 0;
        cur = tree[cur][path];
    }
    return p[cur];               // p = 经过此处的串数 = 前缀为 s 的串数
}
// find：返回这个【整串】出现了几次（0 = 不存在）
int find(const string &s)
{
    int cur = 0;
    for (char c : s)
    {
        int path = get_num(c);
        if (!tree[cur][path]) return 0;   // 边不存在 → 整串一定不存在
        cur = tree[cur][path];
    }
    return e[cur];                        // e[] = 在这个节点【结束】的串数
}

// erase：删掉一个 s（s 不存在就什么都不做）
// ⚠️ 必须【先确认整串存在】。否则删一个"只是别人前缀"的串（例如只插过 abc 却删 ab），
//    会把 p[] 一路减到 0，连带把 abc 所在的分支整条砍掉 —— 不报错、不崩溃，只是答案错。
void erase(const string &s)
{
    if (find(s) == 0) return;             // ① 先探路：整串不存在直接返回

    int cur = 0;
    p[cur]--;                             // ② 与 insert 开头的 p[0]++ 对称
    for (char c : s)
    {
        int path = get_num(c);
        if (--p[tree[cur][path]] == 0)    // ③ 减的是【子节点】的计数
        {
            tree[cur][path] = 0;          // ④ 砍的是【父亲那条边】
            return;                       //    cur 还没下移，所以不需要额外存 pre
        }
        cur = tree[cur][path];            // ⑤ 最后才下移
    }
    e[cur]--;                             // ⑥ 与 insert 结尾的 e[cur]++ 对称
}
~~~

**解释**

- **状态**：节点编号 `cur`。根编号为 **0**，新节点从 `1` 开始 `++idx` —— 所以 `tree[cur][path] == 0` 天然可以当"边不存在"的标记，**千万别把根编成 1**。
- `tree[cur][path]`：字符 `path` 对应子节点的**编号**（不是 bool）。
- `p[cur]`：**经过**该节点的串数 → 回答"前缀计数"。
- `e[cur]`：**在该节点结束**的串数 → 回答"是否存在 / 出现几次"。`p` 管前缀，`e` 管整串，别混。
- **复杂度**：插入 / 查询 O(len)；节点数 ≤ 总字符数 + 1（每个字符最多开一个新节点）。
- **多测清空**：只清 `0 .. idx` 用过的节点（每个节点的 62 条边都要清）。直接 `memset` 整张表，清的是几亿字节，必超时 —— 这一点你在 8306 的注释里已经写了。

### ⚠️ 内存：字典树最容易翻车的地方

先把这道算式自己算一遍：

$$节点数 \times 字符集大小 \times sizeof(元素) = 3\times10^6 \times 62 \times 4\ \text{B} = 744\ \text{MB}$$

`P_8306` 和 `P_2580` 都是这个量级。它能在洛谷过，是因为洛谷限制给得宽；**换到 256MB 的环境（牛客 / CF 常见）直接 MLE，而且不报错、不崩，就是过不去**。三个方向：

| 方向 | 效果 | 代价 |
| --- | --- | --- |
| **缩小字符集** | K 从 62 → 26，内存直接省 58% | 只处理小写字母时可行 |
| **稀疏存边**（每节点挂 `map`/`unordered_map`） | 只为真实存在的边付钱 | 常数大、缓存不友好 |
| **换存储类型** | `int` → `short` / `char`? | **通常没用**：节点数 3e6 已超过 65535，只能 `int` |

结论：**字典树的数组大小永远要按"节点数 × 字符集"估一遍内存，再去看题目限制** —— 这比边界条件更容易翻车。

## 01-Trie（最大异或对）

~~~ cpp
const int N = 1e5 + 10;
int tree[32 * N][2];   // 每个数 32 位 → 最多 32N 个节点
int e[32 * N];         // 记录"走到该叶子代表哪个数"
int idx;

void insert(int a)
{
    int cur = 0;
    for (int i = 31; i >= 0; i--)   // 从高位到低位，这是关键
    {
        int path = (a >> i) & 1;    // 第 i 位
        if (tree[cur][path] == 0) tree[cur][path] = ++idx;
        cur = tree[cur][path];
    }
    e[cur] = a;
}

int query(int a)       // 返回 max(a ^ x)，x 取遍已插入的数
{
    int cur = 0, ret = 0;
    for (int i = 31; i >= 0; i--)
    {
        int path = (a >> i) & 1;
        if (tree[cur][path ^ 1])   // 贪心：先试着走相反位
        {
            ret |= (1 << i);       // 这一位能异或出 1
            cur = tree[cur][path ^ 1];
        }
        else
            cur = tree[cur][path]; // 走不了相反位，这一位只能是 0
    }
    return ret;                    // 也可以 return e[cur] ^ a
}
~~~

**解释**

- **为什么必须从高位到低位**：第 $i$ 位的权重 $2^i$ 大于它**所有低位之和**（$\sum_{j<i} 2^j = 2^i - 1$）。所以"这一位能不能异或出 1"比后面所有位加起来都重要 → **逐位贪心就是全局最优**。这是 01-Trie 的全部理论依据。
- **查询**：尽量走 `path ^ 1`（相反位，异或出 1）；走不了才走 `path`。
- **两种取答案方式**（你两份代码都用过）：
  - 边查边算 `ret |= (1 << i)` —— 不需要 `e[]`，省一层空间；
  - 走到叶子后用 `e[cur]` 取回那个数，最后 `e[cur] ^ a` —— 更直观，但要多开一个 `e[]`。
- **节点数上界**：$n \times 位数 + 1$。`n = 1e5`、32 位 → `32*N` 刚好够，**再加一个数就得多算一格**。
- **内存**：`32 \times 10^5 \times 2 \times 4\ \text{B} \approx 25.6\ \text{MB}$ + `e[]` 12.8MB ≈ 38MB，比普通字典树友好得多（字符集只有 2）。

## 复杂度

### 时间

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| 建树（插入 n 个串，总长 L） | O(L) | 每个字符最多新建 1 个节点，均摊 O(1) |
| 单次插入 | O(\|s\|) | 沿 \|s\| 条边走到底 |
| 单次查询（前缀 / 整串） | O(\|s\|) | 同上，**与串数 n 无关** |
| 01-Trie 插入 / 查询 | O(B) | B = 位数（32 / 61） |
| 删除 | O(\|s\|) | 维护 `p[]` / `e[]` 计数即可，不用真删节点 |
| 多测清空 | O(用过的节点数 × K) | 只清 `0..idx`，别 `memset` 整张表 |

**最关键的一条**：字典树单次操作是 $O(|s|)$，**里面没有 $\log n$**。

- `map<string,int>` 每次查询要 $O(|s|\log n)$ —— 比 $\log n$ 次，每次比较又要比 $|s|$ 个字符；
- 字符串哈希是期望 $O(|s|)$，但存在被卡到 $O(n|s|)$ 的可能（出题人构造冲突）；
- 字典树给的是**确定界**，且前缀类查询哈希根本做不了 —— 这两点合起来才是它的不可替代之处。

> 代价是**常数**：数组版一次 `tree[cur][path]` 是纯寻址，但 K 越大缓存越不友好；`map` 版则每个节点都要哈希/树查找。所以 K 小的场景（01-Trie、小写字母）字典树又快又省，K 大的场景要重新权衡。

### 空间

$$节点数 \le L + 1 \quad(\text{普通 Trie}), \qquad 节点数 \le n \cdot B + 1 \quad(\text{01-Trie})$$

数组版：$O(节点数 \times K)$；稀疏存边版：$O(节点数 + 边数)$。

- **空间只跟"总字符数 L"和"字符集 K"有关，跟串数 n 无关** —— L 相同的 100 个长串和 $10^6$ 个短串，占用一样；
- K 是空间主因：62 叉换 26 叉直接省 58%；
- 01-Trie 的位数 B 也是空间主因：数值 $< 2^{20}$ 时用 20 位就够，节点数降到 3/5 左右。

### 横向对比

| 做法 | 建表 | 单次查询 | 空间 | 前缀统计 |
| --- | --- | --- | --- | --- |
| 暴力 | O(1) | O(n·\|s\|) | O(1) | ✓ |
| 排序 + 二分 | O(n\|s\| log n) | O(\|s\| log n) | O(L) | 部分 |
| `map<string,int>` | O(n\|s\| log n) | O(\|s\| log n) | O(L) | ✗ |
| 字符串哈希 | O(L) | O(\|s\|) 期望 | O(L) | ✗ |
| **普通字典树** | **O(L)** | **O(\|s\|)** | O(L·K) | ✓ |
| **01-Trie** | O(nB) | O(B) | O(nB·2) | — |

### 什么时候**不值得**用字典树

- 只要**整串相等**、不要前缀 → 哈希更快更省（空间差一个 K 倍）；
- 串数很少（$n \le 10^3$）→ 建树开销 > 暴力，直接 `map` 或枚举；
- 字符集巨大（任意 Unicode、$10^5$ 个不同字符）→ 数组版必爆，只能稀疏存边，那时 $O(|s|)$ 的常数优势也没了。

## 死亡回放：我自己踩过的坑

### 1. 旧写法里的三个 bug（已注释掉，但值得留着）

~~~ cpp
int i = 31, tmp = a;
while (tmp) {
    int path = 0;
    if ((tmp & (1 << i)) == 1) path = 1;   // bug1
    tmp <<= 1;                              // bug2
    i--;
    ...
}
~~~

- **bug1**：`tmp & (1 << i)` 的结果要么是 `0`、要么是 `1 << i`，**只有 `i == 0` 时才等于 1**。想判这一位是不是 1，应该写 `!= 0` 或 `(a >> i) & 1`。
- **bug2**：`tmp <<= 1` 是把位往**高位**挪，而 `i` 在**递减** → 每轮测的根本不是你以为的那一位，错位了。
- **bug3**：`while (tmp)` 在高位被移出去之后就提前结束 → 走不满 32 层，树的深度不够。

改成 `int path = (a >> i) & 1;` 一次性解决三个。**这段注释比删掉有价值**，它是"我踩过"的证据。

### 2. 用一个全局变量当"查不到"的哨兵

`P_2580` 里的 `int& find(string&s)`：返回引用，是为了让调用方能直接 `find(s)--` 标记"已点过"；查不到时返回全局 `c` 兜底。这个写法**很巧但很脆**：

- 一旦有第二个查不到的串，或者调用方不小心对返回值做写操作，就会**静默改到 `c`**；
- 不报错、不崩溃，只是答案错 —— 最难查的一类 bug。

**规则**：哨兵只在"能一眼看完所有调用点"时用；否则让函数返回 `int`（或返回指针 + 判空），把判断权交回调用方。

## 选型对比

| 做法 | 建表 | 单次查询 | 空间 | 能做的事 |
| --- | --- | --- | --- | --- |
| 排序 + 二分 | O(n log n) | O(len·log n) | 小 | 只判**整串**存在性 |
| `map<string,int>` | O(n·len·log n) | O(len·log n) | 小 | 整串存在性 / 计数 |
| 字符串哈希 | O(n·len) | O(1) | 小 | 整串相等（**不支持前缀统计**） |
| **字典树** | O(总长) | **O(len)** | **大** | 前缀统计、前缀枚举、01-Trie |
| 01-Trie | O(n·位数) | O(位数) | 中 | 异或最优 / 异或第 k 大 |

一句话选型：**只要出现"前缀"，就用字典树；只查整串相等，哈希/`map` 更省空间。**

## 常见坑（对应 `note.md` 的错因标签）

| 坑 | 错因标签 |
| --- | --- |
| 数组按"串数"开，而不是"总字符数 × 字符集" | `时间` / `边界` |
| 多测 `memset` 整张表 → 超时 | `时间` |
| 根节点编成 1，导致 `tree[x][c] == 0` 不再能表示"边不存在" | `逻辑` |
| `p[]` 和 `e[]` 用混（前缀数 vs 整串数） | `逻辑` |
| **删一个不存在的串**（尤其是"只是别人前缀"的串，如只插过 `abc` 却删 `ab`）→ `p[]` 被减到 0，**连带把别人的分支整条砍掉**。必须先 `find(s)` 确认整串存在 | `逻辑` |
| **删除时"减谁 / 砍哪条边"错位**：`--p[子节点]` 要减**子节点**；`tree[cur][path] = 0` 要在 `cur` **下移之前**执行（那时 `cur` 还是父亲） | `逻辑` |
| **局部变量 / 函数参数与全局数组同名**（如 `for (auto e : s)` 遮蔽了 `int e[N]`）→ 编译错误，或静默读到错的值 | `实现` |
| 01-Trie 只走 `path` 不走 `path ^ 1`，或忘了 `ret \|= (1 << i)` | `逻辑` |
| 01-Trie 的位数开少（`31` 写成 `30`，或没算 `a[0]` 的负数位） | `边界` |
| 查询答案超过 `int`，忘了 `long long` | `类型` |

## 自测

- **普通字典树**：随机生成一批短串（只含小写），建树后暴力统计"以 s 为前缀的串数"对拍；重点测 **`s` 本身就是某个串、`s` 比所有串都长、`s` 不在树中** 三种情况。
- **`erase` 这类「带计数器的删除」必须对拍**（脚本已写好：`Trie/trie_stress.cpp`）：
  随机 200 次 `insert / erase / find / query_prefix`，**每做一步就遍历全部候选串**，和 `map` 暴力版逐一比对
  —— 只在操作之后抽查会漏掉状态漂移，必须**全量比对**。
  必须覆盖的四个点：① 删不存在的串 ② 删"只是别人前缀"的串 ③ 删完再查前缀 / 再 `find` ④ 重复串 + 前缀链。
  **让 bug 高密度出现的关键：字母表只放 `a` / `b`、串长 ≤ 4** —— 这样"前缀串""重复串"才会大量撞上。
  运行：`clang++ -std=c++20 -O2 -I "C:\Users\wait" trie_stress.cpp -o trie_stress.exe`，然后 `.\trie_stress.exe`
- **多测**：连续 3 组数据，检查第 2 组是否受到第 1 组的污染（这是"清空"最容易错的地方）。
- **完成标准**：模板写完 → ① **编译通过** → ② **对拍通过** → 才算完成。
  这个 `erase` 前后改了 6 版，最后是**对拍**把它定案的 —— **计数类 bug 靠读代码看不出来。**
- **01-Trie**：`n ≤ 100` 的随机数组，暴力双重循环求最大异或对，对拍；重点测 **全 0、只有 1 个数、最大值恰好在最高位** 三种边界。
