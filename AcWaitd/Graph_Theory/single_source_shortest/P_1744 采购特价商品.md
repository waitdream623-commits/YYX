
### 💀 死亡回放与漏洞剖析

**1. 致命错误：用 `memset` 初始化 `double` 数组**

```cpp
  memset(dist, INF, sizeof dist); // ❌ 绝对不要对 double 数组这么做！

```

* **解析**：`memset` 是按字节（Byte）赋值的。对于 `int` 数组，每个字节赋成 `0x3f`，拼起来是 `0x3f3f3f3f`，恰好是一个很大的正整数。但是！对于 `double` 类型的浮点数，内存结构完全不同（基于 IEEE 754 标准），把它的每个字节都填充为 `0x3f` 后，得到的值根本不是无穷大，而是一个毫无意义的极小值！这会导致你的 Dijkstra 一开始就认为所有点都非常近，彻底乱套。
* **修正**：遇到 `double` 数组的初始化，老老实实写 `for` 循环：`for(int i=1; i<=n; i++) dist[i] = 1e18;`（用一个足够大的数代表无穷大）。

**2. 隐蔽漏洞：建成了单向图**

```cpp
  edge[a].push_back({x,b}); // ❌ 只加了 a 到 b 的边

```

* **解析**：题目背景通常是城镇之间的道路，这种基于坐标距离的图默认是双向连通（无向图）的。你只存了 `a -> b`，这会导致从 `b` 无法回到 `a`。
* **修正**：需要存双向边：`edge[a].push_back({x, b}); edge[b].push_back({x, a});`。

**3. 格式杀手：没有控制保留小数**

```cpp
  cout<<dist[t]; // ❌ 题目通常要求保留两位小数

```

* **解析**：洛谷 P1744 要求输出保留两位小数的浮点数。C++ 默认的 `cout` 遇到浮点数会省略末尾的 0，或者变成科学计数法，必定触发 WA。
* **修正**：引入 `<iomanip>` 头文件，并在输出时加上 `cout << fixed << setprecision(2) << dist[t];`。

### 🚨 为什么不能混用cin与printf？（底层原理解析）

在你代码的 `main` 函数开头，有这样两句极其经典的“加速外挂”：

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);

```

这两句代码的威力极大，但代价就是**必须舍弃 C 语言的 I/O**，原因如下：

1. **解除绑定的副作用**：默认情况下，C++ 的 `cin/cout` 为了兼容 C 语言，会和 `scanf/printf` 绑定在一起，共用同一个输出缓冲区。这就是为什么平时 `cin` 和 `scanf` 混用不出错的原因。但这种绑定会让 `cin/cout` 变得极其缓慢。
2. **`sync_with_stdio(false)` 的作用**：这句话的作用就是**斩断** C 和 C++ 之间的联系！让 `cin/cout` 拥有自己独立的缓冲区，从而实现速度的狂飙（基本能和 `scanf` 一样快，甚至更快）。
3. **混用的灾难**：一旦联系被斩断，如果你在代码里一会儿用 `cout`，一会儿用 `printf`，它们就会把数据写进各自**不同**的缓冲区里。在最终把数据推向屏幕（或评测机）时，输出的顺序会**彻底混乱**。比如，代码里明明 `printf` 写在 `cout` 后面，终端里却可能显示在前面。这交到洛谷或者比赛评测机上，必然是全屏的 **WA**。

### 💡 算法竞赛中的两条“铁律”

在平时刷题打比赛时，关于输入输出，你只能在以下两条路中**二选一**，绝对不能脚踏两只船：

**路线一：纯 C++ 路线（你目前正在走的，强烈推荐）**

* **配置**：加上 `ios::sync_with_stdio(false); cin.tie(nullptr);`
* **规则**：全程**只准使用** `cin` 和 `cout`。
* **格式化输出**：如果遇到像 P1744 这种需要保留小数的，不要退回去用 `printf("%.2f")`，而是引入 `<iomanip>` 头文件，使用 `cout << fixed << setprecision(2) << 变量;`。

**路线二：纯 C 路线（适合极度复杂的字符串或时间格式化）**

* **配置**：**绝对不要写** `ios::sync_with_stdio(false);`。
* **规则**：全程使用 `scanf` 和 `printf`。

你现在的代码风格非常符合现代 C++ 算法选手的标准（使用 `auto`、`vector`、`pair`），所以请坚定地走**路线一**，把 `cin/cout` 用到底！
