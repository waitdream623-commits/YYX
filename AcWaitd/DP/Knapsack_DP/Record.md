## DP 初始化：恰好装满 vs 最多装满

**状态转移方程通常一样，唯一区别在初始化。**

### 物理意义

| 类型 | 含义 |
|------|------|
| 最多装满（容量上限） | 装 ≤ V 即可，不超就行 |
| 恰好装满 | 必须一丝不差填满，差 1 都是非法 |

### 三种初始化模板

| 场景 | 初始化 | 原理 |
|------|--------|------|
| 求 max 价值（最多装满） | 全部 0 | 装 0 体积也是合法状态 |
| 求 max 价值（恰好装满） | f[0]=0，其余 -INF | 非零容量初始不可达，标记防止被转移 |
| 求 min 代价（恰好装满） | f[0]=0，其余 INF | 同上，求 min 用极大值标记 |

### 为什么只改初始化就够？

设物品体积 3，价值 10，求恰好装满的 max：
```
f[5] = max(f[5], f[2] + 10)
```
若 f[2] 还是 -INF（没被合法凑出），则 f[2]+10 仍是极小负数，f[5] 不会选它。
→ 合法状态只能从合法状态转移来，非法状态通过 -INF/INF 跳过。

### P1509 的教训

- 题目是 **最多装满**（不用花光钱），但初始化成 INF 强行变成"恰好"
- 如果最优解剩了钱，f[m][d] 永远无法被访问 → INF 输出了错
- **判断方法**：看题目是否要求 "必须全部花完/填满"

### 双关键字（pair）的初始化陷阱

P1509 中 pair 存 {人数, 时间}，全部初始化为 0，为什么"时间 0"不会导致 min 误选？
1. 人数增加时：无条件覆盖，不触发 min
2. 人数相等时：新时间已是被之前覆盖过的真实值，min 正常工作
3. 人数为 0 时：min(0, 10) = 0 → 得到 0 个 GF 最小耗时就是不做事（耗时 0），逻辑完美

## DP 初始化完整速查表

| 问题类型 | 初始化 | 关键点 |
|---------|--------|--------|
| 求 max（最多装满） | 全部 0 | 所有容量初始合法 |
| 求 max（恰好装满） | f[0]=0，其余 -INF | 非零容量"有毒" |
| 求 min（恰好装满） | f[0]=0，其余 INF | 如凑硬币 |
| 求 min（至少装满） | f[0]=0，其余 INF | 转移用 `max(0, j-v[i])`，溢出算 0 |
| 计数 / 方案数 | 0，f[0]=1 | 刚好花完求方案 |
| 多目标 pair | 视首要目标定 | 首要 max→0/-INF，首要 min→INF |

### "至少装满" 求最小花费（高频坑）

```cpp
memset(dp, 0x3f, sizeof dp);
dp[0] = 0;
for (int i = 1; i <= n; i++)
    for (int j = V; j >= 0; j--)           // 注意：循环到 0，不卡 v[i]
        dp[j] = min(dp[j], dp[max(0, j - v[i])] + w[i]);
// max(0, j-v[i]) 是核心：溢出部分直接算 0 容量，一个即可满足
```

### 初始化三问

1. 状态含义：f[j] 是"最多"、"恰好"、还是"至少"？
2. 不选是否合法：什么都不选，哪些容量是合理的？
3. 不可达状态的值：应该阻止还是允许后续转移？
