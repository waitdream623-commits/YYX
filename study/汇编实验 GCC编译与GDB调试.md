# 汇编实验 GCC 编译与 GDB 调试

本笔记整理本次实验用到的编译、生成汇编文件、生成可执行文件、运行和 GDB 调试方法。示例文件为 `eg0201.c`，操作在 Linux 虚拟机的终端中进行。

此前实验使用 openEuler ARM64 环境，源码目录为 `/wait`。后续实验请以实际目录、类型大小和调试结果为准。

## 1 区分终端与 GDB

看到类似下面的提示符，表示当前在 Linux 终端：

```text
[root@主机名 wait]#
```

此时可以输入 `cd`、`gcc`、`./eg0201`、`gdb ./eg0201` 等命令。

看到下面的提示符，表示当前在 GDB 中：

```text
(gdb)
```

此时输入 `break main`、`run`、`p x`、`x/4bx &x` 等调试命令。

**复制命令时，不要复制提示符。** 下面的代码块均省略提示符。

## 2 进入源码目录

在终端执行：

```bash
cd /wait
pwd
ls
```

- `cd /wait`：进入 `/wait` 目录。
- `pwd`：显示当前所在目录。
- `ls`：列出目录中的文件，确认有 `eg0201.c`。

`/wait` 是绝对路径；`./wait` 是当前目录下的 `wait` 子目录，两者含义不同。

## 3 直接生成可执行文件并运行

```bash
gcc -g -O0 eg0201.c -o eg0201
./eg0201
```

第一条从 C 源码生成可执行文件；第二条运行它。不必先手动生成 `.s` 文件。

| 参数 | 含义 |
|---|---|
| `gcc` | 调用 GCC 编译器 |
| `-g` | 保留调试信息，方便 GDB 显示源码和变量 |
| `-O0` | 关闭优化，便于初学时观察程序；最后一位是数字 `0` |
| `eg0201.c` | 输入的 C 源文件 |
| `-o eg0201` | 指定输出文件名为 `eg0201`；`-o` 是小写字母 o |
| `./eg0201` | 运行当前目录中的 `eg0201` |

Linux 可执行文件不要求带 `.exe` 后缀。编译成功时通常没有输出；如果出现编译错误，先修复错误，不要把旧可执行文件的运行结果当成新代码的结果。

**每次修改源码后，都要重新编译，再运行或调试。**

如需检查格式符等问题，可以增加警告选项：

```bash
gcc -Wall -Wextra -g -O0 eg0201.c -o eg0201
```

## 4 生成汇编文件

```bash
gcc -g -O0 -S eg0201.c -o eg0201.s
```

`-S` 表示生成汇编源文件后停止，本条命令不会生成新的可执行文件。

查看汇编内容：

```bash
cat eg0201.s
```

如果报告同时要求汇编文件和可执行文件，分别执行：

```bash
gcc -g -O0 -S eg0201.c -o eg0201.s
gcc -g -O0 eg0201.c -o eg0201
```

两次使用相同的优化设置，方便对应分析。`-Og` 中最后一位是字母 g，它也是一种优化设置，与 `-O0` 不同；若指导书明确要求 `-Og`，按指导书统一设置。

## 5 理解几个文件之间的关系

```text
eg0201.c  →  eg0201.s  →  eg0201.o  →  eg0201
 C源码        汇编源码       目标文件       可执行文件
```

需要分步观察时，可以执行：

```bash
gcc -g -O0 -S eg0201.c -o eg0201.s
gcc -g -c eg0201.s -o eg0201.o
gcc eg0201.o -o eg0201
```

`-c` 表示生成目标文件后停止，不进行链接。目标文件 `.o` 不能直接当作程序运行。

如果已有符合当前平台、采用正常 C 运行库入口 `main` 的汇编源文件，也可以直接汇编并链接：

```bash
gcc -g eg0201.s -o eg0201
```

采用 `_start` 自定义入口的程序需要按指导书使用对应链接方式。ARM64 与 x86 指令不同，汇编源码必须与目标平台匹配。

## 6 启动 GDB 并停在 main

先在终端编译，再进入 GDB：

```bash
gcc -g -O0 eg0201.c -o eg0201
gdb ./eg0201
```

进入 GDB 后依次输入：

```gdb
set pagination off
break main
run
```

| 命令 | 含义 |
|---|---|
| `set pagination off` | 关闭长输出的分页暂停 |
| `break main` | 在 `main` 函数处设置断点，可简写为 `b main` |
| `run` | 启动程序，可简写为 `r` |

停在断点时，GDB 会显示对应源码行，通常该行尚未执行。本实验的变量是全局变量，进入 `main` 时已完成初始化；局部变量则要注意是否已经执行到初始化语句之后。

## 7 查看变量的地址和值

| 想查看的内容 | 命令示例 |
|---|---|
| 变量地址 | `p &x` |
| 按变量自身类型显示值 | `p x` |
| 有符号十进制整数 | `p /d x` |
| 无符号十进制整数 | `p /u u` |
| 十六进制整数 | `p /x u` |
| 字符及其编码 | `p /c c` |
| 浮点数 | `p f` 或 `p d` |
| 字符数组内容 | `p str` |
| 类型 | `ptype x` |
| 占用的字节数 | `p sizeof(x)` |

`p` 是 `print` 的简写，`&` 表示取地址。例如：

```gdb
p &u
p /u u
```

第一条查看 `u` 存在哪里，第二条查看 `u` 的无符号十进制值。

`p /u u` 中，`/u` 是显示格式，最后的 `u` 才是变量名。变量叫 `l`，不代表格式要写成 `/l`；查看 `long l` 的十进制值仍然使用 `p /d l`。

浮点变量直接使用 `p f`、`p d`，不要用 `/d` 强制按整数格式显示，否则可能看到小数部分消失的结果。

## 8 查看变量的内存字节

先查大小，再读取相应数量的字节。例如：

```gdb
p sizeof(l)
```

如果结果是 `8`，则输入：

```gdb
x/8bx &l
```

`x/8bx &l` 可以拆成：

| 部分 | 含义 |
|---|---|
| 开头的 `x` | 查看内存的命令 |
| `8` | 读取 8 个单位 |
| `b` | 每个单位是 1 字节 |
| 后面的 `x` | 按十六进制显示 |
| `&l` | 从变量 `l` 的地址开始读取 |

**读取多少字节由 `sizeof` 决定，与变量值有多少位数字无关。** 以下是此前实验的实测大小，换环境时重新查询。

| 变量 | 字节数 | 查看内存 |
|---|---:|---|
| `x`、`u` | 4 | `x/4bx &x`、`x/4bx &u` |
| `l`、`ul` | 8 | `x/8bx &l`、`x/8bx &ul` |
| `s`、`us` | 2 | `x/2bx &s`、`x/2bx &us` |
| `c`、`uc` | 1 | `x/1bx &c`、`x/1bx &uc` |
| `str` | 16 | `x/16bx &str` |
| `str1` | 6 | `x/6bx &str1` |
| `ps` | 8 | `x/8bx &ps` |
| `f` | 4 | `x/4bx &f` |
| `d` | 8 | `x/8bx &d` |

如果变量只有 2 字节，却读取了 4 字节，后面的字节可能属于其他变量或填充区域，不能全部填进该变量的存储栏。

## 9 区分指针的地址与指向的内容

对于下面的定义：

```c
char str[] = "Hello Assembly!";
char *ps = str;
```

| 命令 | 查看什么 |
|---|---|
| `p &ps` | 指针变量 `ps` 自己的地址 |
| `p /x ps` | `ps` 保存的地址，也就是它指向的位置 |
| `x/8bx &ps` | 指针变量自身的 8 个存储字节；先确认指针大小 |
| `x/8bx ps` | 从指向的位置读取 8 字节，即字符串开头的字节 |
| `x/s ps` | 从指向的位置按字符串显示 |

**报告要求填写指针变量自身的存储时，使用 `&ps`。**

`p /d &str` 显示的是数组地址的十进制形式。查看字符数组各元素的十进制编码，可以使用 `p /d str`。

## 10 怎么读小端存储结果

GDB 的内存字节按地址从低到高排列。小端存储把数值的低有效字节放在低地址。

```text
数值：       0x80000000
按字节分组： [80] [00] [00] [00]
小端存储：   [00] [00] [00] [80]
```

十六进制每两位构成一个字节，只调整字节之间的顺序，字节内部的 `80` 不会变成 `08`。

另一个例子：`0x12345678` 的小端存储为 `78 56 34 12`。

地址和值可能因重新编译、系统设置或运行而变化，报告中要填写本次实际观察的结果。

## 11 执行程序与查看源码

| 命令 | 作用 |
|---|---|
| `list` 或 `l` | 显示源码 |
| `next` 或 `n` | 执行到下一源码行，通常不进入被调用函数 |
| `step` 或 `s` | 执行一步，需要时进入被调用函数 |
| `continue` 或 `c` | 继续执行，直到下一断点或程序结束 |
| `info breakpoints` | 查看断点 |
| `delete 1` | 删除编号为 1 的断点 |
| `disassemble main` | 查看 `main` 的反汇编 |
| `quit` 或 `q` | 退出 GDB |

程序仍在运行时，按 `Ctrl+C` 可以中断并回到 GDB 提示符。退出时若询问是否终止被调试程序，输入 `y` 并回车。

GDB 中直接按空回车通常会重复上一条命令。对于查看内存的 `x` 命令，可能继续显示后续地址；为避免记录错变量，填写表格时建议明确输入完整命令。

## 12 常见错误

| 现象 | 原因与处理 |
|---|---|
| 在 `(gdb)` 后输入 `./eg0201`，提示未知命令 | GDB 中用 `run`；要在终端运行则先 `quit` 退出 |
| `p x/1bx &c` 报错 | `p` 和 `x` 是不同命令；改成 `x/1bx &c` |
| `p /l l` 或 `p /ul ul` 报错 | 使用有效格式：`p /d l`、`p /u ul` |
| `x/8bx *d` 报错 | `d` 是普通浮点变量，查看其存储应使用 `x/8bx &d` |
| `p /d &str` 得到一个较大的整数 | 得到的是地址；查看内容用 `p str` 或 `x/s str` |
| `p /d f` 显示 `-100` | 强制使用了整数格式；改用 `p f` 查看浮点值 |
| GCC 提示 `stray '\343'` 等非法字符错误 | 检查是否从文档复制了全角空格，替换成普通半角空格 |
| `gdb: command not found` | 尚未安装 GDB；此前 openEuler 环境使用 `yum install -y gdb` 安装 |
| `apt-get: command not found` | 包管理器不适用；用 `cat /etc/os-release` 查看系统，再选择安装方式 |
| `Missing separate debuginfos` | 此前提示缺少的是系统库调试信息，不影响已带 `-g` 编译的本实验变量观察 |

如果 `printf` 的格式符与参数类型不匹配，或格式符数量超过传入参数数量，输出不能作为可靠实验依据。指针地址可用 `printf("%p\n", (void *)ps);` 输出。

## 13 实验时的最短操作清单

终端中：

```bash
cd /wait
gcc -g -O0 -S eg0201.c -o eg0201.s
gcc -g -O0 eg0201.c -o eg0201
./eg0201
gdb ./eg0201
```

GDB 中，以 `u` 为例：

```gdb
set pagination off
break main
run
p sizeof(u)
p &u
p /u u
x/4bx &u
quit
```

这里 `x/4bx &u` 的 `4` 应与前面 `sizeof(u)` 的结果一致。观察其他变量时，替换变量名、显示格式和字节数即可。
