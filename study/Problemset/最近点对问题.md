# 平面最近点对：分治思路与踩坑总结

题目：哪两个点之间的距离最近【增强版】

## 1. 题目与最终定位

给定平面上的若干点，找出最近点对，输出两点坐标及欧氏距离。输入已按横坐标升序排列。输出时，坐标保留两位小数，距离保留三位小数；坐标和较小的点放在前面。

本次调试中，用户最终确认：在其当时的代码版本中，把 `if(d2<d1)` 改成 `if(d2<=d1)` 后通过评测。

两种写法求出的最短距离相同，但等距时保留的点对不同：

| 写法 | 左右递归距离相等时 |
| --- | --- |
| `if(d2<d1)` | 保留左侧点对 |
| `if(d2<=d1)` | 采用右侧点对 |

**这不是最近点对算法必须选右边，而是本题已通过版本采用的等距选择行为。** 题面说“第一对”，却没有明确枚举顺序，不能单凭题面推导出“第一对就是输入编号最小的一对”，也不能推导出“等距必须选右边”。对于本题，保留已验证版本的行为；对于其他题，按其明确规定处理等距情况。

## 2. 分治状态与过程

```cpp
double getmindis(int l,int r,
                pair<double,double>&x,
                pair<double,double>&y)
```

- `[l,r]`：当前处理的点集，`nodex` 始终按横坐标有序。
- 返回值：当前区间内最近点对的距离。
- 引用参数 `x、y`：返回距离所对应的两个点。

### 2.1 递归边界

只有两个点时，直接返回它们及其距离。

只有一个点时，不存在点对，返回正无穷：

```cpp
return numeric_limits<double>::infinity();
```

不要随意用 `1e9` 作为无效值：当真实距离更大时，它反而可能被当成最优距离。题目需要至少两个点才存在答案；若允许 `n<2`，须另行规定输出。

### 2.2 分别求左右答案

```cpp
int mid = (l+r)>>1;
double d1 = getmindis(l,mid,x,y);
double d2 = getmindis(mid+1,r,x2,y2);
```

先得到左右两部分的最近距离，再令 `d=min(d1,d2)`。但只记录 `d` 不够，还必须记录与它对应的点对。

本题通过版本的选择方式：

```cpp
if(d2<=d1)
{
    x = x2,y = y2;
    d = d2;
}
else
    d = d1;
```

注意：左侧结果直接写入 `x、y`，不需要另外声明没有使用的 `x1、y1`。

### 2.3 合并：处理跨越分割线的点对

左右递归只能保证各自内部的最近点对。全局答案还可能由左边一个点、右边一个点组成，因此不能直接返回 `min(d1,d2)`。

设分割线为 `midx=nodex[mid].first`。若某个跨区间点对距离小于当前的 `d`，两点都必须位于分割线附近。因此只收集：

```cpp
abs(nodex[i].first-nodex[mid].first)<=d+EPS
```

且 `i` 必须属于当前的 `[l,r]`。只收集当前区间，便于维护递归含义和复杂度。

### 2.4 按纵坐标排序并剪枝

把候选点 `tmp` 按纵坐标升序排序，随后只向后枚举：

```cpp
for(int i = 0;i<(int)tmp.size();i++)
{
    for(int j = i+1;j<(int)tmp.size();j++)
    {
        if(tmp[j].second-tmp[i].second>d+EPS)break;
        //计算距离，尝试更新答案
    }
}
```

依据是：

$$
\operatorname{dist}(P_i,P_j)
=\sqrt{(x_i-x_j)^2+(y_i-y_j)^2}
\ge |y_i-y_j|.
$$

当纵坐标差超过允许范围时，距离也必然超过允许范围；后续点的纵坐标更大，可以直接 `break`。

只向后枚举还能避免重复比较同一对点，无须再判断 `j==i`。

本题通过版本在合并时只接受严格更近的点对：

```cpp
if(t<d)
{
    x = tmp[i],y = tmp[j];
    d = t;
}
```

**左右等距选右边，与合并等距不更新，是两处不同的规则。** 不要为了“统一”而随意把所有 `<` 改成 `<=`。

## 3. 点对选择与输出顺序是两件事

点对选择回答“选哪两个点”，输出顺序回答“选中的两点谁在前”。

在 `main` 输出前统一处理：

```cpp
if(x.first+x.second>y.first+y.second)swap(x,y);
```

不要只在合并更新时交换，因为答案可能来自两个点的递归边界，根本没有经过合并更新。

确定的反例：

```text
2
0 10
1 0
```

正确输出：

```text
(1.00,0.00),(0.00,10.00),miniDist=10.050
```

另外，两个点的坐标和相等时，上述判断不会交换。因此：

```cpp
x = tmp[i],y = tmp[j];
```

和下面的写法可能输出不同：

```cpp
x = tmp[j],y = tmp[i];
```

已通过版本采用前一种写法。清理代码时应保留，不要额外按输入编号或坐标字典序交换。

## 4. 为什么不能凭经验只比较前后各4个点

原代码使用 `i-4` 到 `i+4`，但没有给出足以支持这个数量的几何证明，不能把它当作可靠模板。

标准最近点对算法可以通过几何装箱证明限制比较数量，但限制取决于候选区域、排序方式、距离是否严格小于以及是否有重合点等前提。学习时优先使用“纵坐标差超过距离就退出”的写法，明确剪枝依据，不要随意记一个常数。

## 5. 重合点与时间复杂度

若大量点坐标完全相同，最短距离为0，纵坐标差也为0，双循环可能一直无法退出，退化到平方级枚举。

通过版本在输入时提前检测重合点。一旦存在，距离必然为0，可以跳过分治。

保留 `ids` 中每个坐标第一次出现的编号，并用 `zid、z` 记录最早形成的重复坐标组。注意：这里的编号表只服务于重合点处理，不参与普通等距点对比较。

在候选点数量满足标准几何装箱条件、重合点已处理的通常复杂度分析下：

- 每层递归重新对候选点排序，时间复杂度为 `O(n log² n)`。
- 递归深度为 `O(log n)`，辅助空间为 `O(n)`；哈希表检测重合点的复杂度为期望复杂度。
- 若递归返回时维护纵坐标有序，并在父层归并，可进一步优化到 `O(n log n)`。

这里的 `EPS` 是微小的绝对筛选容限。如果点之间的尺度小到大量点落在该容限内，严格的常数候选数量论证可能不再适用；不能把固定绝对容限当作适合任意实数尺度的保证。

## 6. 浮点数处理：本题保留的规则

本题通过版本中，`EPS=1e-12` 只扩大候选筛选范围：

```cpp
abs(x-midx)<=d+EPS
dy>d+EPS
```

答案比较仍是：

```cpp
d2<=d1
t<d
```

不能擅自改成“距离差小于EPS就按编号比较”。那是另一套答案选择规则，可能改变输出。

浮点误差确实存在，例如 `0.4-0.3` 与 `0.5-0.4` 在二进制浮点运算中可能不完全相等。但“存在误差”不等于“任意添加EPS就能修复评测”。固定容限也可能把真实不同的距离视为相等。若题目要求精确处理固定小数位的输入，可考虑按已知小数位放大为整数、比较距离平方；这需要先知道输入精度和数值范围，本题题面未明确给出。

## 7. 精简代码（保留已通过版本的关键行为）

下面是依据用户确认通过的版本清理冗余后的代码。保留 `nodex、getdis、getmindis、l、r、mid、x、y、d、d1、d2、tmp、ids、z、zid` 等命名，以及原有距离计算表达式和候选排序方式。清理版仍需单独提交评测，不能把来源版本的通过结果直接当成清理版的评测结果。

```cpp
#include <bits/stdc++.h>
using namespace std;

const double EPS = 1e-12;
vector<pair<double,double>>nodex;
pair<double,double>z;
int n,zid = INT_MAX;

struct H
{
    size_t operator()(pair<double,double> p)const
    {
        return hash<double>{}(p.first)^
               (hash<double>{}(p.second)<<1);
    }
};

unordered_map<pair<double,double>,int,H>ids;

double getdis(pair<double,double> i,pair<double,double> j)
{
    return sqrt(pow(i.first-j.first,2)+pow(i.second-j.second,2));
}

double getmindis(int l,int r,pair<double,double>&x,
                pair<double,double>&y)
{
    if(l==r)
    {
        return numeric_limits<double>::infinity();
    }

    if(r-l+1==2)
    {
        x = nodex[l],y = nodex[r];
        return getdis(x,y);
    }

    int mid = (l+r)>>1;
    pair<double,double>x2,y2;
    double d;
    double d1 = getmindis(l,mid,x,y);
    double d2 = getmindis(mid+1,r,x2,y2);

    if(d2<=d1)
    {
        x = x2,y = y2;
        d = d2;
    }
    else
    {
        d = d1;
    }

    vector<pair<double,double>>tmp;
    for(int i = l;i<=r;i++)
    {
        if(abs(nodex[i].first-nodex[mid].first)<=d+EPS)
        {
            tmp.push_back(nodex[i]);
        }
    }

    sort(tmp.begin(),tmp.end(),[](const auto&a,const auto&b)
    {
        return a.second<b.second;
    });

    for(int i = 0;i<(int)tmp.size();i++)
    {
        for(int j = i+1;j<(int)tmp.size();j++)
        {
            if(tmp[j].second-tmp[i].second>d+EPS)break;

            double t = getdis(tmp[i],tmp[j]);
            if(t<d)
            {
                x = tmp[i],y = tmp[j];
                d = t;
            }
        }
    }

    return d;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n;
    nodex.resize(n+1);

    for(int i = 1;i<=n;i++)
    {
        cin >> nodex[i].first >> nodex[i].second;

        if(!ids.count(nodex[i]))
        {
            ids[nodex[i]] = i;
        }
        else if(ids[nodex[i]]<zid)
        {
            zid = ids[nodex[i]];
            z = nodex[i];
        }
    }

    //少于两个点没有点对，题面未定义其输出
    if(n<2)return 0;

    //保留来源版本的排序行为
    sort(nodex.begin()+1,nodex.end());

    pair<double,double>x,y;
    double dis;

    if(zid<INT_MAX)
    {
        x = y = z;
        dis = 0;
    }
    else
    {
        dis = getmindis(1,n,x,y);
    }

    if(x.first+x.second>y.first+y.second)swap(x,y);

    printf("(%.2f,%.2f),(%.2f,%.2f),miniDist=%.3f",
           x.first,x.second,y.first,y.second,dis);

    return 0;
}
```

为什么题面已保证按横坐标排序，还保留一次排序？因为这里的目标是清理已通过版本，而原版本的 `sort(pair)` 会在横坐标相同时按纵坐标进一步排序。这可能改变等距点对的遍历顺序，因此不把它当作纯粹无影响的操作随手删除。

## 8. 原代码与修改中的问题清单

| 问题 | 影响或处理 |
| --- | --- |
| 从1开始使用固定数组 | 数组长度为10005时只能安全存至下标10004；改为按n+1分配 |
| 单点返回1e9 | 不是真正无穷大，可能错误参与最小值比较 |
| 仅在合并时调整输出顺序 | 递归直接返回的答案可能没有经过调整 |
| `x=tmp[j],y=tmp[i]` | 两点坐标和相等时，最终输出顺序可能与通过版本不同 |
| `d2<d1` | 左右等距时选左侧，与已通过版本的`<=`不同 |
| 在普通等距比较中加入编号优先 | 改变了已通过版本的选点规则 |
| 编号排序和坐标字典序先后执行 | 后一套规则可能覆盖前一套结果 |

| 大量重合点 | 可能导致枚举退化，提前检测零距离 |

| point、node、x1、y1 | 未使用，可删除 |
| key与best | 对最终通过版本的答案选择没有作用，可删除 |

## 9. 调试复盘：为什么前面反复修改没定位到

1. **没有先区分距离错误、点对错误、输出顺序错误。** 最近距离相同，不代表具体坐标输出相同。
2. **把题面歧义当成了确定规则。** “第一对按输入编号最小”只是解释之一，没有证据时不应不断围绕它增加逻辑。
3. **同时修改了多个因素。** 左右等距优先级、编号、浮点容限、输出顺序混在一起，难以判断哪个修改起作用。
4. **误读通过提示。** 页面提示与提交详情不一致时，应核对具体提交的时间、代码、分数和测试点结果。本次曾把提示误认为全部通过，是排查失误。
5. **对拍只能验证预先设定的规则。** 与“按编号优先”的暴力程序一致，只能说明满足该规则，不能证明参考答案也采用它。

更可靠的顺序是：保存原版本 → 修复有反例证明的问题 → 每次只改变一个选择规则 → 核对该次提交详情 → 对通过版本只做不改变行为的清理。
