## 关键转化

### CF 2274B Prefix

[题目链接](https://codeforces.com/contest/2274/problem/B) ｜ [代码](../../AcWaitd/CF/CF_2274_B.cpp)

## 题目核心

- 依次处理 i = 2…n：设 s 为**当前数组**的前缀和，把 a[i] 换成 a[i] − s、a[i]、a[i] + s 之一。
- 最大化最终数组里最大元素的值。

## 关键转化

三种选择 = 把当前前缀和 P 变成 P′ = a[i] + k · P（k ∈ {0, 1, 2}）：

| 选择     | 新前缀和 P′       |
| -------- | ----------------- |
| a[i] − P | a[i]（重置）      |
| a[i]     | a[i] + P          |
| a[i] + P | a[i] + 2P（翻倍） |

第 i 步产出的元素值 = a[i] − P、a[i] 或 a[i] + P，只由当时的 P 决定 → 想取最大，只需要 P 的极值（要 +P 用最大 P，要 −P 用最小 P）。

## 做法

维护可达前缀和的最小 / 最大值 smin、smax（初值都是 a[1]）。对每个 i = 2…n：

1. 本步最大值 `best = max(a[i], a[i] - smin, a[i] + smax)`（用**更新前**的 smin / smax）
2. 更新前缀和范围：
   - `smax = max(a[i], a[i] + smax, a[i] + 2*smax)` —— P 是正的就翻倍冲最大，否则重置回 a[i]
   - `smin = min(a[i], a[i] + smin, a[i] + 2*smin)` —— 负的翻倍冲最小，否则重置
3. `ans = max(ans, best)`，答案初值为 a[1]

为什么只维护两端就够：固定 k 时 P′ = a[i] + k·P 随 P 单调，取极值只用到 P 的极值；单步的 best 也只由两端决定，中间的 P 不可能更优。

## 易错点

- 前缀和更新用的是**原始 a[i]** + k·P，不是"替换后的值"（踩过：把前缀和跟每个位置替换后的 f[i][0/1] 混在一起，极值越滚越离谱）
- 正侧取 **max**、负侧取 **min**（踩过：newmax 写成 min，样例 `1 2 3` 会错输出 5，正确 7）
- best 必须用**更新前**的 smin / smax
- long long：n = 50 时数值可达约 5.6×10¹⁶（≈ 50 × 2⁵⁰），32 位装不下

## 复杂度

- 每组 O(n)，额外空间 O(1)

# C

## CF 2274C Lavencia Oranges

[题目链接](https://codeforces.com/contest/2274/problem/C) ｜ [代码](../../AcWaitd/CF/CF_2274_C.cpp)

## 题目核心

把 n 个橘子放进 n 个袋子。设 c[x] 为恰好装了 x 个橘子的袋子数，代价为 `max(x * c[x])`。求最小代价，并输出每个橘子的袋子编号。

约束：`1 <= n <= 200000`，所有测试的 n 之和不超过 200000。

## 我的思路：二分答案 + 按袋子大小降序构造

假设代价不能超过 mid，那么每种大小 x 都必须满足：

```text
x * c[x] <= mid
c[x] <= floor(mid / x)
```

非空袋子的大小不会超过 mid，因此最多能装的橘子总量为：

```text
F(mid) = sum(x * floor(mid / x)), x = 1..mid
```

`F(mid) >= n` 时可行。随着 mid 增大，每种大小允许的袋子数都不会减少，所以可行性单调，可以在 `[1, n]` 二分最小可行值。

## 构造与正确性

设最小可行答案为 k。依次考虑袋子大小 `k, k-1, ..., 1`，每种大小 x 最多分配 `floor(k / x)` 个袋子。每装满一个袋子就换一个编号，输出该编号 x 次；输出满 n 个编号后结束。

- 必要性：代价不超过 k 时，每种大小最多贡献 `x * floor(k / x)` 个橘子，总量不可能超过 F(k)。
- 充分性：F(k) 足够时，按上述顺序分配一定能装下 n 个橘子。非空袋子数不会超过橘子数，因此编号也不会超过 n。
- 如果最后一个袋子只装了 r 个橘子（r < x），此前只用过大小不小于 x 的袋子，尚未用过大小 r。这时 `c[r] = 1`，贡献 r 不超过 k，不会破坏代价上界。

所以容量判定与实际构造是匹配的，尾袋不装满也没问题。

## 我的错点：判定一直累减，导致 int 溢出

原来的判定使用 `int s = n`，把所有大小的容量都减完后才判断 `s <= 0`。虽然 n 不超过 200000，但二分初期的 mid 很大，累计容量仍可能超过 int 的范围，导致判定错误。

合法反例：

```text
1
102199
```

原程序首行输出 72265，正确答案为 352：`F(351) = 101443`，`F(352) = 102199`。

第一次二分取 `mid = 51100`，容量为 2147672687，全部扣完后的数学结果是：

```text
s = 102199 - 2147672687 = -2147570488
```

低于 int 下限，发生有符号整数溢出，破坏二分判定。小数据能通过并不能排除这个问题。

## 修复：提前退出本身就足够

每次扣除的容量都是正数，一旦 `s <= 0`，就已经证明容量够了，可以立即返回 true。

**本题保留 int，只加提前退出就能避免溢出，不是必须改 long long。** 因为每次扣除前 s 都是正数，而 `mid / x * x <= mid <= 200000`，扣除后 s 最低只到 -199999，随后立即退出。

```cpp
auto cheack = [&](int mid) -> bool {
    int s = n;
    for (int x = mid; x > 0; --x) {
        s -= mid / x * x;
        if (s <= 0) return true;
    }
    return false;
};
```

也可以只改为 `long long s`，全部扣完后再判断，仍然正确。当前代码同时使用 long long 和提前退出，后者也减少了不必要的计算。

## 其他注意点

- 每个大小最多分配 `k / x` 个袋子，不是每种大小总共放 k 个橘子。
- 输出的是橘子对应的袋子编号，不是各袋子的大小。
- 构造方案不唯一，第二行与样例不同并不代表错误，应检查实际代价是否等于最优值。

## 复杂度与验证

不提前退出时，单次判定 O(mid)，二分判定总计 O(n)，构造和输出 O(n)，额外空间 O(1)。提前退出能减少判定的实际计算量。

修复后通过了 1069 个本地用例的最优值和构造合法性检查，包括小规模枚举、随机输入、溢出反例和 n = 200000。该结果是本地验证，不是在线提交记录。
