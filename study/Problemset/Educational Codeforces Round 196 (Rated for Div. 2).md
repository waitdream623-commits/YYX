## B · 将周期字符串转化为整除计数

题目输入就是整数数组：从长度为 `10^18` 的全 0 串出发，对每个 a[i]，将位置为 a[i] 倍数的字符置为 1。要求删除尽量少的数组元素，使字符串的最小周期内恰好有一个 1。[官方题面](https://sas.codeforces.com/problemset/problem/2283/B)与[官方题解代码](https://sas.codeforces.com/blog/entry/158495?mobile=true)均与当前本地 B 文件对应。此前仅凭字符串题名判断源码不符，是整理时的错误，已更正。

设保留数组的最小值为 m，则第一个 1 位于 m，位置 2m 也一定为 1。若字符串满足条件，设最小周期为 p，则第一个周期内唯一的 1 必须位于 m，所以 p ≥ m；所有 1 的位置构成 m、m+p、m+2p、……。由于 2m 也是 1，有 m = kp，其中 k 为正整数；结合 p ≥ m，得到 p = m。

因此所有保留值必须是 m 的倍数，否则会在非 m 倍数的位置额外产生 1。反过来，只保留 m 和它的倍数，字符串就恰好在 m 的倍数位置为 1，满足要求。

枚举数组中的 a[i] 作为 m，统计 `a[j] % a[i] == 0` 的数量，取最大值 best，答案为 `n - best`。排序后只需枚举 j ≥ i；重复最小值由它第一次出现时的枚举完整统计，不会漏掉最优解。排序耗时 O(n log n)，枚举耗时 O(n²)，题目保证所有测试的 n 之和不超过 5000，可以通过。

例如 `[6,10,20,30]`：保留最小值 6 时可留 `[6,30]`；保留最小值 10 时可留 `[10,20,30]`，因此最少删除 1 个。不能只固定原数组最小值。

## C · 异或按位看奇偶，从高位决定选择

当前代码用 `cnt[i][j]` 表示整数 `1..i` 中第 j 位为 1 的数量，`msb[i]` 表示 i 的最高有效位。

异或结果的第 j 位等于这一位的 1 的数量对 2 取模，因此判断异或位只需判断计数奇偶。正整数 x 翻倍就是二进制左移一位：原第 j 位的 1 移到第 j+1 位。更新方式为：

```cpp
if ((x >> j) & 1) {
    count[j]--;
    count[j + 1]++;
}
```

设 x 的最高位为 b。翻倍会改变第 b+1 位及更低位，不会改变更高位。比较非负整数大小时，最高的不同位决定大小，因此可以从大到小处理，围绕第 b+1 位的当前奇偶决定选择。当前实现先选 n，之后仅在 `now[n][msb[i]+1]` 为偶数时选择 i，使该位翻为 1。

### 复制范围可以缩小

当前每次查询复制整张前缀表：

```cpp
vector<array<int, 20>> now(cnt, cnt + n + 1);
```

但后续只访问、修改 `now[n]`，因此可以只复制第 n 行：

```cpp
auto count = cnt[n];  // array<int, 20> 按值复制，修改 count 不影响 cnt[n]
```

之后把 `now[n][j]` 改为 `count[j]` 即可。这样每次查询复制 20 个整数，无需复制 n+1 行；计数工作区从 `O(nB)` 缩小为 `O(B)`，其中 B 为位数，答案数组仍为 `O(n)`。此处记录优化方法，本次未修改源文件。

预处理只执行一次，各查询从原始 `cnt[n]` 获取独立副本，避免上一次查询的修改影响下一次。因为更新访问 `j+1`，分配位数时需要容纳最大输入翻倍后的最高位。

## D · 邻接表清空与并查集状态

**D 已通过，这题最值得记住的是“先按首要目标缩小候选，再把路径问题转成连通块问题”。**

- **先最大化黑点数。** 偶数 `n` 取 `k=n+1`，所有点都能配对，直接最优。奇数 `n` 最多有 `n-1` 个黑点，只需考虑 `k=n、n+1、n+2`，分别留下 `n、(n+1)/2、1` 这个点。
- **再判断剩下的点能否变灰。** 设剩下的点为 `start`，需要存在一对合法配对点，使它们的路径经过 `start`。
- **路径经过某点，可以转成删点后的连通性。** 删去 `start` 后，若某对配对点属于不同连通块，它们的路径就必然经过 `start`。

你这次实现上的主要教训：

| 问题               | 应记住的规则                                   |
| ------------------ | ---------------------------------------------- |
| 用 `fill` 清邻接表 | `fill` 改元素，`clear` 才删除元素              |
| 多轮检查残留 `fa`  | 每次检查前完整初始化；查询可能涉及尚未访问的点 |
| 迭代路径压缩顺序错 | 保存旧父亲 → 修改当前父亲 → 沿旧父亲继续       |
| 算出根却连接原节点 | 并查集合并应连接 `fx、fy`                      |

用户贴出的超时版本在多测开始使用 `fill(edge[i].begin(), edge[i].end(), 0)`。这只把旧邻居编号变成 0，不删除元素；随后 `push_back` 新边，邻接表长度继续累积，DFS 还会额外访问不存在的 0 号节点。应改为 `edge[i].clear()`。

合法压力输入可以取 10000 组相同的三点链 `1-2-3`，总 n 仅 30000。第 t 组的邻接表总长度已增长到 4t，所有组的累计存储遍历量可达 O(T²)，而正确清空后是 O(总 n)。本机用 g++ C++20、O2 对当前源文件做对照：原版约 0.811 秒，仅替换 clear 的版本约 0.058 秒，两者均输出 10000 行。这是本地耗时对比，不代表修改后已通过线上评测。

还需分别修正以下问题：

- 迭代 find 的第二轮应先保存旧父亲，再执行 `fa[x] = root`，最后沿旧父亲向上走。原来的 `x = fa[x]; fa[x] = root;` 跳过了原始查询节点的压缩。
- 合并应该连接根：`fx != fy` 时执行 `fa[fx] = fy`。本题按 DFS 父子顺序合并时可能恰好连接了根，但通用函数不能忽略已经算出的 fx、fy。
- 每次更换候选 k 前，完整初始化 `fa[1..n]`。DFS 中会查询尚未访问的 `k-x`，仅在进入节点时初始化 fa[x] 不够；未访问节点可能仍保存上轮关系或默认值 0。
- 判断有效配对时显式排除 `k-x == x`，并排除剩下的非黑节点 start。
- 题面允许 n 达到 300000，链状树的递归深度可达 n。后续可改用显式栈，或删除 start 后对各连通块迭代标号，检查配对两点是否属于不同连通块。[官方题面](https://sas.codeforces.com/problemset/problem/2283/D) · [官方解法](https://sas.codeforces.com/blog/entry/158495?mobile=true)
