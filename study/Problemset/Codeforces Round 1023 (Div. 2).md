## C. Maximum Subarray Sum

[题目链接](https://codeforces.com/problemset/problem/2107/C) ｜ [本地代码](<../../AcWaitd/Contest/Codeforces Round 1023 (Div. 2)/C_Maximum_Subarray_Sum.cpp>)

题意：只能修改 `s[i] = '0'` 的位置，使整个数组的最大非空子数组和恰好为 `k`；已知元素必须保留。

### 我的思路：极小负数隔断 + 左右贡献补齐

1. 所有未知位置先填 `-1e18`，隔开已知区间。用 Kadane 求当前最大子数组和 `omax`。
2. `omax > k`：已知区间已经超标，无法修改，输出 `No`。
3. `omax == k`：当前构造已经满足要求。
4. `omax < k`：若没有未知位置则无解；否则选择一个未知位置 `p`，其余未知位置保持极小负数。

状态含义要准确：`pre[i]` 是**以 i 结尾**的最大非空子数组和，`suf[i]` 是**以 i 开头**的最大非空子数组和，不是整个前缀或后缀中的最大值。

```cpp
ll left = max(0LL, pre[p-1]);
ll right = max(0LL, suf[p+1]);
a[p] = k - left - right;
```

左右贡献可以不取，因此与 `0` 取最大。经过 `p` 的子数组最大和为 `left + a[p] + right = k`；不经过 `p` 的已知区间不会超过 `k`，其他未知位置的极小负数负责隔断。时间、空间复杂度均为 `O(n)`。

### 这次错点：寻找未知位置时漏掉末尾

```cpp
// 错误：i 最多走到 n-1，唯一的 0 在末尾时会修改已知位置。
while(i+1<n && s[i-1]!='0') i++;

// 修复：i 是从 1 开始的下标，要允许访问最后一个位置。
// 当前分支已有 cnt > 0，保证能找到 0。
while(i<=n && s[i-1]!='0') i++;
```

最小规模反例：	

```text
1
2 5
10
1 0
```

原程序输出 `[5, -1e18]`，虽然最大子数组和是 `5`，但改掉了已知值 `a[1] = 1`。修复后得到 `[1, 4]`。

### 一句话复盘

构造思路正确，AI 协助定位了循环边界错误；修复后通过 3533 组本地校验，尚未确认在线 AC。以后搜索位置先测目标在首位、末位和不存在；检查构造时同时验证目标值与已知元素是否保留。

## D. Apple Tree Traversing

[题目链接](https://codeforces.com/problemset/problem/2107/D) ｜ [本地代码](<../../AcWaitd/Contest/Codeforces Round 1023 (Div. 2)/D_Apple_Tree_Traversing.cpp>)

**状态：原提交已 AC**，用户截图用时 **4468 ms**、内存 **33900 KB**；当前源码已做性能优化，优化版完成本地验证，尚未重新在线提交。

我的思路：两遍 BFS 找直径，删除直径上的节点，继续处理剩余森林。首版有下面三个问题，第二版的修复检查记录在本节末尾。

> [!IMPORTANT]
>
> 删除一条直径后，划分为许多小树，大小不一，需要记录答案排序输出。
>
> 对于找小树的start与end，不要访问不属于该树的
>
> 相同距离选择大的节点

### 1. 删除顺序与输出顺序

题目要求整个序列字典序最大，要优先比较 `(路径点数, 较大端点, 较小端点)`。`unordered_set::begin()` 不能代表当前最优连通块，找到一条直径就立即输出会出错。

反例：

```text
1
8
1 2
2 3
1 4
4 5
1 6
6 7
1 8
```

本地原程序输出 `(5,7,5), (1,8,8), (2,3,2)`；正确顺序为 `(5,7,5), (2,3,2), (1,8,8)`。删除第一条直径后，长度为 2 的路径要排在孤立点前面。

修改方向：每个连通块都正确选择直径后，收集所有三元组，最后按字典序降序输出。不同连通块互不影响，删除节点也不会产生更长的路径，因此可以这样整理输出顺序。

### 2. 最远点只能在本次 BFS 到达的点中选择

原程序 BFS 后扫描所有 `vis` 中的节点，但其他连通块未访问的 `dist` 也为 0。当起点是孤立点时，`>=` 会把别的连通块中编号最大的节点选为 `start`，这个点未必是直径端点。

已复现的 14 点反例中，首次删除后剩下孤立点 `1、11` 与路径 `10—13—12`。从孤立点 `1` BFS 后，全局扫描误选 `13`，最终取 `(2,13,12)`，漏掉真正的直径 `(3,12,10)`。仅排序输出无法修复这个问题。

修改方向：第一次 BFS 保存本次访问的 `nodes`；两次选择最远点时都只遍历 `nodes`，相同距离取较大编号。`start` 从本次起点 `a` 初始化。

### 3. 每轮处理全部 n 个位置会退化为 O(n²)

原程序每轮新建长度为 n 的 `last/dist`，还两次遍历 `1..n`。星形树首轮只删除 3 个节点，剩下 n-3 个孤立点，每轮仍做 O(n) 的全量处理，总复杂度退化为 O(n²)。

修改方向：数组每个测试只分配一次；每轮只访问和更新当前连通块中的节点，BFS 起点的距离、父节点单独重置。

“会超时”的表述过于绝对：本次原提交实际已经 AC，但重复初始化仍有 O(n²) 开销，后续优化见本节末尾。

### 一句话复盘

局部最优状态只在本次访问的连通块内使用；全局答案另按字典序组织；复杂度要把循环次数乘上每轮初始化、扫描的成本。以上为首版复盘，后续修复和优化记录如下。

### 第二版检查：父节点、同距离编号、数组初始化

第二版已增加当前连通块的 `node`，并把三元组收集后降序输出。当时还有两处正确性问题和一处可优化开销：

1. **第二次选择 `end` 时不能清空 `last`。** `last` 保存第二遍 BFS 的父节点，后面要靠它回溯直径。删除该循环中的 `last[e] = 0;`；第一次选择 `start` 时的清空可以保留，用于准备第二遍 BFS。最小反例是 `n=2`、边 `1 2`：`start=1, end=2`，父节点被清空后回溯变成 `2 → 0 → 0`，无法结束。
2. **`node` 是 BFS 访问顺序，不能用 `>=` 代替编号比较。** 同距离时显式取较大的编号，两次选择端点都要改：

   ```cpp
   if(dist[e] > dist[start] ||
      (dist[e] == dist[start] && e > start))
       start = e;
   ```

   找 `end` 时把比较中的 `start` 换成 `end`。仅修复父节点后，4 点星形树 `1—2、1—3、1—4` 会输出 `(3,3,2), (1,4,4)`，正确答案是 `(3,4,3), (1,2,2)`。
3. **`last/dist` 仍在 `while` 中分配，星形树仍是 O(n²)。** 将数组分配移到 `while` 外；每轮第一次 BFS 前设置 `last[a] = 0; dist[a] = 0;`，防止复用上一轮状态。

按上述三处修改后的测试版本通过 1503 棵小树的全路径枚举对拍，以及 150000 点星形树检查。用户随后截图确认本题已在线 AC。

### AC 后的性能优化

- `last/dist` 移到循环外，每组测试只分配一次；每轮第一遍 BFS 前将 `last[a]、dist[a]` 置零，其余访问点的状态在遍历时覆盖。
- `unordered_set` 改为 `vector<char> vis`，`vis[x] = 1` 表示节点尚未删除；查状态、删除都直接访问数组。
- 用单调向右的指针 `a` 找起点，只有 `vis[a] = 0` 时才前进，起点扫描总计 O(n)。直径可能不经过 `a`，不能每处理一次直径就无条件 `a++`。

两遍 BFS、端点比较和三元组降序排序保持原来的思路。消除重复全量初始化与哈希查找后，按下文的分裂深度证明，所有 BFS 总计 O(n√n)，排序 O(n log n)，整体为 O(n√n)。

### 贪心、排序与 O(n√n) 的证明

以下根据用户提供的题解整理，直径长度 d 按节点数计算。

**1. 为什么贪心选择最大的 `(d,u,v)`？**

字典序由第一个不同的数字决定，所以当前必须先取最大的三元组：先最大化路径点数 d，再最大化端点 u、v。相同端点在树上对应唯一一条路径，因此固定这个三元组后，剩余森林也固定，可以对后续操作继续使用同样的论证。

**2. 为什么删除一条直径后，所有子连通块的直径都严格变短？**

先证明同一棵树的任意两条直径必相交。假设两条直径不相交，暂将它们的长度按边数记为 L，用两条路径间的最短连接段接起来。从连接点分别走向各自直径的较远端点，两边长度都至少为 L/2；连接段至少有一条边，因此能组成一条长度至少为 L/2 + 1 + L/2 > L 的简单路径，与 L 是直径矛盾。

所以，删除直径 P 时，原树所有同长度的直径都会被破坏。任一子块若仍有原来的直径长度，就会产生一条与 P 不相交的原树直径，矛盾。因此子块直径严格小于父块直径。该性质针对被分裂的连通块，其他独立连通块不受影响。

**3. 为什么可以先分块处理，最后统一降序排序？**

父块对应三元组的第一项 d，严格大于它分出的所有子块的第一项，因此降序排序一定让父块操作排在子块前面。不同分支的操作互不影响，可以交换顺序。于是排序后的操作仍然合法，且等价于每一步都选择当前最大的三元组，满足第 1 点的贪心规则。

**4. 为什么分裂深度最多 O(√n)？**

沿着任意一条父块到子块的链，设依次删除的直径点数为：

$$
d_1 > d_2 > \cdots > d_k \ge 1.
$$

这些直径删除的节点互不重复，因此总和不超过 n；同时它们是严格递减的正整数，最小也要取 k、k-1、…、1，所以：

$$
\frac{k(k+1)}{2} \le d_1+d_2+\cdots+d_k \le n,
\qquad k \le \sqrt{2n}.
$$

这里必须是正整数，不能把结论推广成任意正实数。

**5. 为什么总复杂度是 O(n√n)？**

将分裂过程看作一棵层次树。同一层的连通块互不相交，所有块的 BFS 总开销为 O(n)；即使邻接表保留了已删除的边，扫描量也不超过原树所有节点的度数之和。总层数最多 O(√n)，所以所有 BFS 总计 O(n√n)。

最多收集 n 个三元组，排序另需 O(n log n)，被 O(n√n) 包含。辅助空间为 O(n)。

注意：O(√n) 是分裂深度，不是总删除次数。星形树只需两层，却会有 O(n) 次删除；如果每次都初始化长度为 n 的数组，仍会退化到 O(n²)。这正是将 `last/dist` 移出循环的原因。
